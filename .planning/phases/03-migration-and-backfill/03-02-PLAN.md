    2. Imports: `import argparse, logging` and `from services.supabase_store import list_by_user` and `from services.patient_store import promote_to_patient_tables`.

    3. Function `run_backfill(user_id: str, dry_run: bool = False, verbose: bool = False) -> dict`:
       - Call `docs = list_by_user(user_id)` to fetch all documents
       - Initialize counters: total=len(docs), skipped=0, promoted=0, errors=0
       - For each doc in docs:
         - If `doc.structured_result is None`: increment skipped, if verbose print "SKIP {doc.document_id} -- no structured_result", continue
         - If `dry_run`: print "DRY-RUN would promote {doc.document_id} ({doc.structured_result.document_family})", increment promoted, continue
         - Try: call `promote_to_patient_tables(doc_id=doc.document_id, user_id=user_id, structured_result=doc.structured_result, upload_date=doc.upload_date.strftime("%Y-%m-%d"))`, increment promoted, if verbose print "OK {doc.document_id}"
         - Except Exception as exc: increment errors, print "ERROR {doc.document_id}: {exc}"
       - Return `{"total": total, "skipped": skipped, "promoted": promoted, "errors": errors}`

    4. Function `verify_completeness(user_id: str) -> None`:
       - Import `_get_client` from `services.supabase_store`
       - Get client, run count queries:
         - `documents WHERE user_id=X AND structured_result IS NOT NULL` (use `.not_.is_("structured_result", "null")`)
         - `patient_observations WHERE user_id=X`
         - `patient_conditions WHERE user_id=X`
         - `patient_medications WHERE user_id=X`
         - `patient_allergies WHERE user_id=X`
         - `patient_imaging_findings WHERE user_id=X`
       - Print all counts in a formatted summary

    5. `if __name__ == "__main__":` block with argparse: `--user-id` (required), `--dry-run` (store_true), `--verbose` (store_true), `--verify` (store_true, runs verify_completeness after backfill). Calls `run_backfill()`, prints summary, optionally calls `verify_completeness()`.

    Key design: This script is intentionally thin — almost all logic is reused from Phase 2's `list_by_user()` and `promote_to_patient_tables()`. The only new logic is the dry-run gate and completeness reporting.
